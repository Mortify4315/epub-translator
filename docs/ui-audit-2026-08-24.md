# UI and Product Audit — 2026-08-24

## Executive Summary

The application had a capable translation engine but presented it as a collection of generic tabs and terminal prompts. The redesign establishes **Jade Scroll Press**, a publication-production interface shared by WebUI and TUI. It makes the real workflow explicit, improves accessibility and mobile behavior, adds operational controls that were missing from the TUI, and adds a first-class local 9Router provider.

## Baseline Findings

### WebUI

- Generic narrow white-card layout with weak product identity and hard-coded visual values.
- Navigation described tools, not the Prepare → Translate → Verify workflow.
- No theme support and no responsive breakpoint; a 390px viewport overflowed horizontally.
- Several controls lacked visible labels or accessible state. Progress, notices, and current navigation were not consistently announced.
- Cost, provider readiness, recovery, and completed output were present but not composed into one legible production flow.

### TUI

- Default panels and repeated prompts made status difficult to scan.
- Glossaries could become an unbounded wall of text and could not be filtered.
- Provider readiness was weakly communicated.
- Pipeline, strict one-pass mode, chapter limit, and translation group size were absent from the settings flow.

### Product Gaps

- No first-class preset for the user's current local router.
- Glossaries had no portable import/export path in the browser.
- Provider switching could preserve a stale base URL unless the caller explicitly replaced it.

## Research and Decisions

English and Chinese searches were run across GitHub and GitLab. Gitea.com and Codeberg public APIs were also searched, but returned no relevant repositories for the selected English/Chinese queries.

Patterns worth adopting:

- **BookForge:** shared job state, pause/resume/retry, doctor/review flows, and WebUI/TUI parity.
- **Honya:** calm literary terminal presentation, review queue, cost visibility, and search.
- **BiTranslator and LinguaHaru:** chapter sampling, history/resume, proofreading, onboarding, and actionable failure states.
- **Lulalala/epub-translator:** a staged wizard, chapter selection, and reusable configuration.
- **Other Chinese-focused EPUB tools:** bilingual output, glossary/style preparation, and consistency audits.

The current iteration adopts the workflow clarity, readiness, filtering, progress, and portability patterns that fit the existing architecture. A full review queue, chapter-level retry desk, and side-by-side reader are valuable future features but require persistent job/revision models and were intentionally not faked as surface-only controls.

## Implemented Improvements

### WebUI

- New responsive app shell with desktop sidebar and mobile navigation.
- Light and dark themes with local preference persistence.
- Publication-docket visual system, bundled Newsreader variable font, and original SVG icon set.
- Prepare/Translate/Verify workflow, readiness status, estimate sheet, live progress, stoppable jobs, resume adoption, log view, and finished-output shelf.
- Searchable editable glossaries with JSON import/export.
- Accessible labels, live regions, semantic progress, current-navigation state, skip link, visible focus, large touch targets, reduced-motion support, and keyboard shortcuts (`Alt+1` through `Alt+5`).
- No gradients, glass effects, emoji controls, or generic AI-chat motifs.

### TUI

- Jade Scroll Press header, consistent Rich theme, and styled Questionary prompts.
- Dashboard showing source/output counts, provider, and readiness.
- More descriptive menus, richer progress display, compact glossary table, and glossary search.
- Settings for provider, pipeline, strict mode, chapter limit, and maximum group tokens.

### Routing and Safety

- Added the local **9Router** preset at `http://localhost:20128/v1` with `fusion-panel`, `qd/auto`, and `qd/ultimate` model choices.
- API key is optional for this local preset; no secret is invented, logged, or sent by the readiness probe.
- Provider switches now apply that provider's base URL and model defaults instead of retaining stale routing.
- A read-only `GET /v1/models` probe returned HTTP 200 from the user's local 9Router instance. No paid completion was submitted.

## Verification

- Full automated suite: **190 passed**.
- JavaScript syntax, Python compilation, and whitespace validation passed.
- Desktop and 390px mobile browser checks passed without horizontal overflow.
- Both themes rendered correctly; the bundled editorial font loaded successfully.
- All major views were exercised, provider selection previewed, and browser console errors/warnings were empty.
- Final interface quality detector found two advisory issues; both were resolved (copy cadence and transform-based progress animation).
